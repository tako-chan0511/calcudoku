# Calcudoku — 計算パズル

3×3〜9×9・easy/normal/hard・演算子・シードを設定できる計算パズルです。初期設定は5×5・normal・四則演算です。Vue 3 + strict TypeScript + Vite + Vitest + Vue Test Utils + ESLintを使用します。

全サイズの問題を数字入力して最後まで解けます。マス選択、キーボードと数字パッド、矢印移動、削除、制約チェック、タイマー、クリア判定、同じ問題での再挑戦を実装しています。初期表示は1マスケージの固定値だけで、正解全体をUIに渡しません。Undo/Redo、2段階ヒント、この問題のベスト記録、自動保存・復元にも対応しています。

## 開発

Node.js **22.22.2以上の22系**とnpmを使用します。`.nvmrc` は22、CIもNode 22です。実装時の検証環境はNode 22.23.4です。依存関係は `package-lock.json` で固定しています。

```sh
cd ~/projects/calcudoku
# nvmを使用している場合: nvm install && nvm use
node --version
npm ci
npm run dev
```

ブラウザでViteが表示するLocal URLを開きます。初回は保存データを検証し、復元できない場合と「新しい問題」でWeb Workerが生成・一意性・難易度を確認します。6×6以上の保存問題の再検証もWorkerで行います。生成中は候補数と段階を表示し、キャンセルできます。生成に失敗した場合は未確認の問題を出さず、直前の確認済み問題と入力・経過時間があれば保持します。


## 遊び方

マスをクリック/タップして、数字パッドまたはキーボードの1〜Nで入力します。盤面にフォーカスがある場合だけ矢印キーで選択移動、Delete/Backspaceで削除できます。Tabで盤面へフォーカスする操作にも対応します。1マス固定ケージは編集できません。

「!」と説明文は行・列の重複、計算条件に矛盾するケージを示します。未完成ケージは成立する組合せが残っていれば警告しません。警告は現在の入力に基づく局所的な判定で、正解との照合やヒントではありません。

タイマーは最初に数字を書き換えた時点で開始します。全N×Nマスの行・列・ケージ条件が成立するとクリアし、時間を停止して編集をロックします。「同じ問題で再挑戦」で問題定義・ケージ・シードを維持したまま入力・選択・時間・警告を初期化します。

新規生成中は入力と再挑戦をロックします。成功時だけ新しい問題へ切り替えて初期化します。失敗時は直前の問題と入力を保持します。生成待機中も、それまでに開始したプレイの時間計測は続きます。

## 履歴・ヒント・記録・復元

- Undo/Redoは入力・上書き・削除を対象とし、実際の新規変更でRedo履歴を破棄します。固定値、時間、答え使用フラグを巻き戻しません。クリア後は編集とUndo/Redoを無効にします。
- 「候補表示」は選択セルの現在値を置き換える場合の、行・列・ケージの制約による局所候補です。他の入力を固定して調べます。矛盾の理由と候補なしも表示し、数字を書き込まず、記録対象からも除外しません。
- 「答えを見る」は明示的なクリック時だけ、問題定義をサイズ別の探索上限内で解き直し、選択セルの数字だけをゲーム状態へ返します。予算超過・複数解では利用不可とし、推測しません。答え使用フラグはUndo後も残ります。
- 問題IDごとに、答えを使わない回の最短時間を保存します。再挑戦ではベスト記録を維持し、新しい回の答え使用状態と履歴を初期化します。
- 途中状態は入力後、計測中は約1秒ごと、ページ離脱時に保存します。再読み込みでは問題構造・ID・固定値・入力範囲・時間・状態を検証し、探索上限内で一意解を再確認してから復元します。
- 保存した経過時間に再開後の単調増加時計を加算し、ページを閉じていた時間は加えません。ページ離脱時は一時停止し、ブラウザの履歴から戻る場合にも再開します。復元後のUndo/Redo履歴と選択状態は新たに開始します。
- 保存するのは公開された問題とプレイヤーの入力・経過時間・状態・答え使用フラグです。内部の正解配列やソルバーの証拠配列は含めません。クリア済みの入力盤面は復元できますが、復元自体を新しいベスト記録として登録しません。
- localStorageが拒否・容量超過になっても、失敗を表示してプレイを続けられます。破損データや未対応バージョンは採用しません。

保存形式・検証・時計の詳細は [docs/persistence.md](docs/persistence.md) を参照してください。

## 設定・再現性・難易度

設定画面は編集中の値です。変更だけでは現在の問題・タイマー・保存状態を変えません。「新しい問題」でその時点の設定をコピーしてWorkerへ渡し、成功後だけ問題を切り替えます。生成中の編集、失敗、キャンセルでも現在の問題は保持します。

シードは0〜4294967295の10進整数です。「ランダムシード」は編集欄だけを更新します。「コピー」は現在プレイ中のシードをコピーします。同じ問題を再現するには、サイズ・難易度・演算子・シード・生成方式をすべて合わせてください。

最新は `calcudoku-v3` です。`latestSettings(seed, size, difficulty, operators)` を使います。v2のAPI `currentSettings()` は同じ問題の再現のため変更せず残しています。旧 `calcudoku-v1` は5×5/normalの生成条件を維持し、旧保存やシードを再現できます。互換API `settingsForSeed()` は旧v1のままです。UIでv1を選ぶと「旧評価」と表示します。

v2/v3の難易度評価は生成時間を使わず、ケージ構成・固定値数・論理解法と探索の必要性で決めます。

- easy: 最大2マスのケージ、単純な候補削減で全マスが決まる。
- normal: 行・列・複数マスのケージ候補を繰り返し組み合わせる、または隠れた単一候補が必要。先読みなしで解ける。
- hard: 上の論理処理が停止し、先読み探索が必要。一意性は探索を完了して確認する。

通常の固定値上限はeasy 45%、normal 20%、hard 12%（切り捨て、最低1）です。v3の二項演算のみでは、最大マッチングで求めた不可避の固定数＋盤面5%の調整余地と通常上限の大きい方を使い、60%を安全上限にします。論理・先読みの難易度評価は変えません。easy/normalは固定値を最低1マス含みます。評価は実装した論理解法に基づき、人間のあらゆる解法の難しさを保証するものではありません。指定評価を満たせなければ、難易度を変更せず失敗します。

生成はサイズ別のwork上限と試行回数で制限します。5以下は単回ソルバー150,000 work、6/7/8/9は350,000/700,000/1,000,000/1,500,000 workです。v2の全体予算は3〜9の順で600,000/2,000,000/4,000,000/6,000,000/10,000,000/16,000,000/24,000,000 workです。v2の試行はeasy/normal 40回、hard 100回。v3は3/4の全体work予算を2,000,000/8,000,000とし、他サイズはv2と同じです。通常100候補、hard/二項演算のみ400候補、3×3 hardは最大1,600候補です。UIは5以下15秒、大きい盤面45秒でWorkerを終了し、未確認問題を採用しません。

`unique` / `multiple` / `unsatisfiable` / `budgetExceeded` / `invalid` を区別し、論理評価モードは `stalled` も返します。1解だけ見つかって予算を使い切った場合も一意とは判定しません。生成条件・乱数順・予算・評価基準を変更するときは版を更新し、v1/v2/v3の固定シード契約テストを維持します。

9×9はマスを56px以上に保ち、盤面内だけを横スクロールできます。数字パッドは1〜Nです。保存する適用済み設定は問題定義に含み、編集中の設定は保存しません。リロード後の編集欄は復元した問題の設定へ戻ります。

## テストと性能

`tests/fixtures.ts`には独立した行順列の参照解法があり、3×3 hardと旧5×5を照合します。全サイズの生成・入力・クリア・描画と演算子15通り、失敗/キャンセル/古い応答/旧保存互換をテストします。

ベンチマークは生成の成功率・中央値・95パーセンタイル・最大時間・消費work・ケージ調整回数を報告します。計測対象は生成処理のみで、その後に行う再ソルバー検証の時間は含めません。失敗したシードも時間集計に含めます。Nodeでの測定であり、スマートフォンやWorker起動時間の保証ではありません。

最新の原因分析・改善前後比較・残課題は [docs/step45-report.md](docs/step45-report.md)、全計測値は [docs/benchmark-v2-v3.json](docs/benchmark-v2-v3.json) を参照してください。v2の測定履歴は [docs/performance.md](docs/performance.md) に残しています。**9×9・除算のみ・hardは生成成功が未確認で、動作保証対象外の条件です（固定シードの評価で0/5件）。** その他にも生成に失敗する条件があり、難易度や一意性を緩めて採用しません。

依存監査の修正版を使用するため、`minimatch` と `glob` の対象バージョンに `overrides` を設定しています。Node 22で通常のpeer依存を満たした状態でlint・テスト・ビルドを検証します。`--force` / `--legacy-peer-deps` は不要です。

## STEP 4.5の改善

v3は小さいhardの領域形状を優先探索し、行を二部マッチングで埋める多様なラテン方格を使います。除算のみは整数除算が成立する辺の最大マッチングで固定セルを最小化します。減算が使える場合は従来の固定セルによる絞り込みも利用します。大盤面normalは最大3マスを優先し、複数解の調整では連結2+2分割と固定数の少ない切り出しを選びます。

失敗は難易度条件・演算子制限・探索上限・試行上限・設定/内部エラーに分けて説明し、別のシード・難易度・演算子を提案します。現在の問題、入力、時間、Undo/Redo、答え使用状態は保持します。
