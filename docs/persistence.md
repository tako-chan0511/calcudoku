# 保存形式・検証・時間管理

## バージョン1

- `calcudoku.session.v1`: `{ version: 1, puzzle, progress }`
- `progress`: `{ values, elapsedMs, status, answerUsed }`
- `calcudoku.bests.v1`: `{ version: 1, records: [{ problemId, elapsedMs }] }`

公開された問題はサイズ・ケージ・シード・難易度・許可演算・問題ID・生成版・一意性マーカーです。プレイヤー入力以外に正解配列を保存しません。履歴・候補・ソルバーの解や証拠を保存しません。保存時はフィールドを明示的にコピーし、不要な実行時プロパティを含めません。

## 復元の判定

1. JSONのサイズとバージョン、必須フィールド・型・未知のフィールドを検証する。
2. 3×3〜9×9・難易度・選択演算・生成版、ケージの被覆・連結・演算・固定値を確認する。
3. 生成条件と実際のケージを含む問題IDが生成版v1の形式に一致することを確認する。
4. 入力N²マスの範囲と固定値、経過時間と状態の整合性を確認する。誤入力による重複・ケージ矛盾は、修正を続けられるように復元する。
5. 保存された一意性マーカーを信用せず、サイズ別のソルバー上限内で一意性を検証し、v2は指定難易度も再確認する。6×6以上はWorkerで確認してから復元する。複数解・解なし・探索超過は採用しない。

readyは固定値だけ・時間0・答え未使用、clearedは空欄なしで全制約成立、playingは未クリアであることを要求します。有限の0〜365日分の時間だけ受理します。セッションJSONは64,000文字まで、ベスト記録JSONは10,000,000文字までとし、書き込みが制限される場合は既存記録を変更しません。

破損・未対応データは復元せず新しい問題を生成します。保存済みのクリア状態を読み込んでも記録を新規登録しません。ベスト記録は実際のクリア操作で、答え未使用かつ既存より短い場合だけ更新します。不正なベストデータは採用せず、次の対象クリアで新しい形式の記録を保存できます。

これはローカルの整合性検証です。正しい型の時間や使用フラグを人為的に書き換える不正行為を、サーバーなしで完全に防止する設計ではありません。

## 時計とライフサイクル

通常は最初の実入力で開始します。復元時は保存済みの経過時間を基準値とし、`performance.now()`による再開後の差分だけを加えます。壁時計や保存日時との差は加算しません。停止・再開を重ねてもタイマーは1本です。

入力・履歴・答え使用状態の変更後、計測中は約1秒ごと、pagehide・visibilitychange(hidden)・コンポーネント破棄時に保存します。pagehideで時計を停止し、pageshowで再開するため、履歴からの復帰でも離脱時間を加算しません。visibilitychangeだけでページが非表示になる場合は保存し、そのページ内での計測は継続します。

クリア・新しい問題の受信・再挑戦・破棄時は時計を停止します。Undo/Redoでは時計と答え使用状態を戻しません。復元後は履歴と選択を初期化します。

## 保存できない環境

ストレージ取得・読取・JSON解析・書き込みをすべて例外処理します。容量超過や保存拒否では既存記録を成功扱いにせず、画面へ失敗を表示してゲームを継続します。保存領域はcalcudoku専用キーだけを使用し、他アプリのキーを削除しません。


## STEP 4の互換性

保存外枠のversion 1は継続します。適用済みのサイズ・難易度・演算子・シード・生成版は `puzzle` に含まれ、draftとは分離します。旧 `calcudoku-v1` の5×5保存と問題ID・記録はそのまま復元し、最新v2へ勝手に置換しません。未知の外枠バージョンや生成版は採用しません。

新しいサイズや設定でも問題IDに生成版と全設定・実際のケージを含むため、ベスト記録を混同しません。問題IDは最大16,000文字を検証します。編集中の設定は保存せず、再開時は適用済み設定を編集欄へ入れます。

6以上の復元はpending扱いで保持し、Workerが一意性と指定評価を確認するまで盤面を公開しません。キャンセルは保存問題を未確認のまま表示せず、要求IDで遅い応答も破棄します。失敗時は安全な既定問題を生成し、現在編集中の設定を自動適用しません。


## v3の保存・復元

外枠version 1は継続し、生成版はv1/v2/v3を区別します。旧版は元のID・設定・記録のまま復元します。v3は従来と同じ一意性・論理評価に加え、二項演算の不可避固定数に応じた上限を検証します。そのために使う正解は検証関数内の一時配列だけで、UI・保存には返しません。

失敗理由用の診断カウンターは生成結果のmetricsに含み、保存された問題やプレイ状態には追加しません。比較測定にあるmatchingMinSinglesTotalは、試行ごとの最小固定数の合計であり、盤面1枚の最小値ではありません。
